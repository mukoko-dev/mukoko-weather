# Real-browser checks

Chromium checks of the production build, for what unit tests cannot see: the service worker, the offline page, in-place place switching and a forecast that does not arrive (issue #414). They read the public weather API through the test browser and refuse every write, so nothing is created in production (`memory-budget.mjs` is the exception: it answers every request itself and needs no network).

Playwright is not a dependency of this repo, so none of these run in CI: they are run by hand, before a release that touches what they cover. Run them where Playwright is installed, or point `NODE_PATH` at its `node_modules`.

```bash
npm run build && npx next start -p 3100 &
BASE=http://localhost:3100 SHOTS=/tmp/shots node scripts/browser-check/pwa-check.mjs
```

| Script                | What it proves                                                                                                                                                                                                                                                                                                                                                                                                    | Takes |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----- |
| `pwa-check.mjs`       | The shell, the worker, switching places without a reload, offline launch (a stored place and a never-stored one), and the slow-forecast line (none before 8 s, one calm line and "Try again" after, no layout shift, "Couldn't load" after the retries, recovery).                                                                                                                                                | 90 s  |
| `offline-shell.mjs`   | Five fresh browsers launched offline: `/` paints the saved place, `/lagos-ng` shows the "You're offline" page and not the error boundary, with no `/_next/` request failing.                                                                                                                                                                                                                                      | 80 s  |
| `bottom-bar.mjs`      | The phone bottom bar's pinned items: Map and Locations are the same width at 340, 375, 393 and 430 px (a preset, not the width of their labels), "Locations" fits whole, the lane keeps room, and below 360 px both are one touch target wide.                                                                                                                                                                    | 40 s  |
| `hero-icon-group.mjs` | The hero's phone icon group: fixed to the top of the screen and level with the hero's top row, still there after scrolling, the profile menu opens under it inside the screen; at 1280 px there is no fixed group and Share is back in the top row.                                                                                                                                                               | 20 s  |
| `offline-retry.mjs`   | The offline page's chunk is refused at install, so it is not stored; one online navigation a minute later stores it (as a script, never as HTML); offline then works.                                                                                                                                                                                                                                             | 90 s  |
| `swipe-warm.mjs`      | A real touch swipe to the next saved place: with the places warmed it paints from memory (about 0.2 to 0.3 s) and asks the Worker for nothing; with Save-Data on (nothing warmed) it waits for the forecast, here held back 800 ms.                                                                                                                                                                               | 70 s  |
| `modal-sheet.mjs`     | Every modal and bottom sheet, real touch: Close at the top right (49 px), pull down from the bar or the content (follows, springs back, closes), scrolled content scrolls, reduced motion, screen-radius corners, centred dialog at 1280 px.                                                                                                                                                                      | 150 s |
| `memory-budget.mjs`   | The memory budget (#476): heap, DOM nodes, listeners, canvases and WebGL contexts of the place page cold, fully scrolled, over 30 place switches, 20 detail-sheet cycles, the map (every layer, timeline playing) and router navigation, each held to a number that is checked. Needs no network (`memory-harness.mjs` answers it). `PROFILE=pixel` runs the Android sky (Three.js), `QUICK=1` the short version. | 8 min |

`harness.mjs` holds what they share; `memory-harness.mjs` holds what the memory check adds (mocked network, canvas and WebGL counting, CDP readings after a forced garbage collection). Exit code 0 is a pass, 1 a failed check, 2 a crash of the harness itself.

Not covered: iOS Safari, Android, a real home-screen install. Those need a device. The memory budget is in particular a desktop Chromium in a phone profile: it catches a page that starts holding more (or a place, sheet or map that is never let go), it does not say how much a real phone allows a tab.
