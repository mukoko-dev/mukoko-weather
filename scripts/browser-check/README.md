# Real-browser checks

Chromium checks of the production build, for what unit tests cannot see: the service worker, the offline page, in-place place switching and a forecast that does not arrive (issue #414). They read the public weather API through the test browser and refuse every write, so nothing is created in production (`memory-budget.mjs` is the exception: it answers every request itself and needs no network).

Playwright is not a dependency of this repo, so none of these run in CI: they are run by hand, before a release that touches what they cover. Run them where Playwright is installed, or point `NODE_PATH` at its `node_modules`.

```bash
npm run build && npx next start -p 3100 &
BASE=http://localhost:3100 SHOTS=/tmp/shots node scripts/browser-check/pwa-check.mjs
```

`first-screen.mjs` includes the Google tag (issue #551). The lab answers every host that is not the app's own, and used to refuse the Google tag's, which left the largest third-party cost of the page out of every number: `gtag.js` for the app's GA4 property is 181 KB gzipped and 542 KB to parse. `gtag-standin.mjs` generates a stand-in of that size at run time (nothing large is committed), serves it from the machine under test through the throttled link, and the page's request for `www.googletagmanager.com/gtag/js` is redirected to it. It stands in for the tag's bytes, their parse and, roughly, the two long tasks the real tag runs when it arrives (two bursts of arithmetic of about 190 ms each at 4x CPU); not for the rest of what the real tag does, nor for the DNS and TLS set-up to Google's host. The tag is reported apart from the app's own JavaScript (`gtagTransferKB`, `gtagStart`, `gtagEnd`). `GTAG=none` restores the old refusal, to compare with numbers taken before this existed; `GTAG_FILE=<path>` serves a copy of the real tag that you saved yourself.

`critical-css.mjs` answers whether the first screen's inline stylesheet subset (src/lib/critical-css, made by scripts/critical-css, issue #551) changed anything a person sees. `coverage` loads `/`, a place page and an unknown place, light and dark, as a first and a return visit, once with the rest of the stylesheet held back and once with it, and compares the computed style of every element (a rule the subset is missing shows as an element that differs; exit 1). `shoot` and `diff` take screenshots at 393x852 of the same scenarios on two builds (`LABEL=before`, then `LABEL=after`; `HOLD_REST=1` for the first paint alone) and count the pixels that differ. `STRIP_CRITICAL=1` is a control: it takes the inline subset out too, and `coverage` must then fail. Reduced motion is on and the page's clock is fixed, so two renders of the same page are the same pixels.

`harness.mjs` holds what they share; `memory-harness.mjs` holds what the memory check adds (mocked network, canvas and WebGL counting, CDP readings after a forced garbage collection). Exit code 0 is a pass, 1 a failed check, 2 a crash of the harness itself.

Not covered: iOS Safari, Android, a real home-screen install. Those need a device. The memory budget is in particular a desktop Chromium in a phone profile: it catches a page that starts holding more (or a place, sheet or map that is never let go), it does not say how much a real phone allows a tab.
