## 1. Tech Stack -> Maps, the "MapLibre v6 worker" sentences (line 28)

These two sentences are already out of date on `staging` (commit 2267d1c, #451)
and stay wrong with maplibre-gl 6.16.0:

> v6 ships its web worker as a separate ES module (`maplibre-gl-worker.mjs` -> imports `maplibre-gl-shared.mjs`) ...
> `scripts/copy-maplibre-worker.mjs` ... copies both files (and their source maps) to `public/vendor/maplibre-gl/<version>/` (gitignored) ...

Suggested replacement for those two sentences:

> v6 ships its web worker as a separate ES module (`maplibre-gl-worker.mjs`) and by default loads it from beside the
> bundled chunk, where webpack never emits it, so the worker fails and every map renders blank.
> `scripts/copy-maplibre-worker.mjs` (logic in `scripts/lib/maplibre-worker.mjs`, run by the `prebuild`/`predev` npm
> scripts) copies the worker, with its source map, plus every relative module the worker actually imports (followed
> transitively), to `public/vendor/maplibre-gl/<version>/` (gitignored). The package has shipped two layouts, so the
> copy is decided by what the worker imports, never by a version number: 6.12.0 is a thin worker importing
> `maplibre-gl-shared.mjs` (both are copied); 6.13.0 and later, checked through 6.16.0, is one self-contained worker,
> and `dist/` keeps an EMPTY `maplibre-gl-shared.mjs` placeholder that nothing refers to (not copied). A module the
> worker names that `dist/` lacks stops the build. `MapLibreMap.test.ts` checks the installed package on every
> maplibre-gl bump.

## 2. Conventions -> new bullet (react-hooks lint rules)

`eslint-config-next` 16.4.x pulls `eslint-plugin-react-hooks` 7.1.x, which fails `npm run lint:eslint` (the CI Lint
step) on `react-hooks/set-state-in-effect` and `react-hooks/refs`. Suggested bullet:

> - **React hooks lint (7.1):** never write a ref during render (`ref.current = x`): keep "latest props" refs current in
>   a `useLayoutEffect` declared before the component's other effects (see `MapLibreMap`), or a no-deps `useEffect`
>   declared before the effect that reads it (see `usePolledJson`). Never call a function that sets state from an effect
>   body, even an async one that sets it after an `await`: the rule follows the call. For a fetch on mount, chain
>   `.then`/`.catch`/`.finally` inside the effect with a `current` flag cleared in the cleanup (see `ApiKeysManager`,
>   `ProfileDevices`, `StatusDashboard`); for browser-only reads after mount, set state from a
>   `requestAnimationFrame` callback (the `useStableNow` pattern); to reset state when a prop changes, compare against
>   a stored key during render (see `overlayKey` in `MapLibreMap`), not in an effect.
